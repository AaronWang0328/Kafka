常泰桥梁防撞系统 · 功能需求说明

面向实施开发方  |  版本 v1.0  |  2026-10-14  |  运行环境：中心服务器 172.61.36.226（Ubuntu 22.04）

1　项目背景与数据源

1.1 总体背景

常泰长江大桥横跨长江主航道，桥区水域船舶流量大、船型复杂。为预防船舶碰撞桥墩、失控偏航、超高刮碰桥体等事故，需建设一套桥区船舶行为监测与预警系统，对进入桥区水域的船舶进行实时感知、行为判定与风险预警。

系统由三类感知手段与一套业务数据共同支撑：

  • 视频感知——桥墩上的云台相机对桥区水面持续观测，识别船舶位置与航态；
  • 激光雷达感知——桥塔上架设的三维激光雷达扫描水面，获取船舶三维点云；
  • AIS / VTS 数据——船舶自动识别与交通管理数据，提供船舶身份、登记尺度与动态位置。

本说明面向实施开发方，明确以下两个功能块需要实现的能力、输入输出与验收标准：

功能块一句话目标解决什么问题
功能一异常告警发生时，自动留存现场图像与视频让值班人员能"看见"告警现场，替代事后到现场取证
功能二用激光雷达三维成像测出船舶真实尺度（尤其高度），与 AIS / VTS 数据融合输出可信高度判定船舶是否超高，为通航管控提供客观依据

3　功能一：异常告警图像 / 视频截取

3.1 功能描述

当系统判定出船舶异常行为时，需在该时刻自动从对应桥区相机留存现场媒体，形成"告警 + 证据"的完整记录。需覆盖的告警类型：

序号告警类型判定依据现场媒体需要呈现的内容
1超高激光雷达测高 + AIS 融合船舶整体轮廓，需能看出船体与水面关系
2偏航偏离主航道船舶与航道边界的相对位置
3超速航速超阈值船舶形态与所处航道
4停船低速滞留船舶位置与滞留水域
5靠近距桥墩过近船舶与桥墩的距离关系
6禁行进入非通航区船舶与禁航区边界的关系
7逆行航向与规定相反船舶首尾朝向
8穿越（横越）跨越航道状态变化船舶穿越过程，建议用视频体现

3.2 输入

告警事件
由业务算法产生的告警消息，须包含：船舶标识（MMSI）、目标经纬度、告警类型、告警时间
视频流
桥区各相机的 RTSP 实时流（已提供推流地址）
坐标映射
相机画面的像素↔经纬度标定参数（用于把告警坐标定位到画面中的船）

3.3 输出要求

产物要求
标注快照JPG，1920×1080。画面中用醒目矩形框标出告警船舶；框旁叠加该船的航迹编号、置信度、经纬度。未匹配到目标时也应保留原图，不得丢记录。
标注视频MP4，建议 15–20 秒、15–25 fps，编码 H.264 + yuv420p + faststart（保证浏览器可直接播放）。录制期间被标注船舶需持续高亮，短暂丢失目标时应沿用最后位置框。
命名与归档按告警类型 / 小时分目录，文件名含船舶标识 + 时间戳，便于检索与留存管理。
对外访问产物需通过 HTTP 静态服务提供，形成可被业务前端直接引用的 URL。
运行记录每条告警需落一条处理记录，至少含：接收时间、命中的相机、匹配结果、产物路径、文件是否真实落盘（含字节数），用于事后核对"没收到"与"收到但失败"。

3.5 需要实现的能力清单

  1. 常驻订阅告警事件，按目标经纬度判断应由哪台相机负责本次留存；
  2. 持续读取各相机视频流并只保留最新帧，避免积压造成延迟；
  3. 对画面做船舶检测与跟踪，为目标分配稳定编号，并转换为经纬度；
  4. 将告警坐标与画面目标做就近匹配（需明确匹配距离阈值）；
  5. 匹配成功则从该时刻起录制标注视频并输出标注快照；匹配失败也需保留现场画面，避免黑天/逆光等场景丢记录；
  6. 产物落盘后回查文件真实存在且非空，并写入运行记录；
  7. 具备断线重连与长跑稳定性（相机断流、进程异常退出后能自动恢复）。

4　功能二：激光雷达三维成像测高与 AIS / VTS 融合

4.1 功能描述

利用桥塔上的三维激光雷达对桥区水面持续扫描，重建出船舶的三维点云，据此测出船舶的长度、宽度与高度；再与 AIS / VTS 的船舶登记数据融合，输出该船可信的高度值，作为超高判定的依据。

为什么必须融合：激光雷达只能测出"当前出现在水面上的那个物体"有多大，无法回答"它是哪艘船、登记尺度多少、当时是否正在通过桥孔"。AIS / VTS 提供船舶身份与登记尺度，两者结合才能给出可追责的结论；同时可用登记尺度对雷达测量结果做交叉校验，识别测量异常。

4.2 输入

激光雷达点云
北醒三维激光雷达输出，逐帧点云（X / Y / Z 坐标），坐标系以雷达为原点，Z 轴垂直向上
AIS / VTS 数据
船舶 MMSI、船名、登记船长 / 船宽、实时经纬度、航速 / 航向
雷达安装参数
安装经纬度、安装海拔、正北朝向角、扫描扇区范围
水面基准
需要明确水位基准（用于把点云 Z 值换算为"水面上高度"）

4.3 需要实现的处理链路

［1］点云获取 按帧读取雷达点云，记录采集时刻 ［2］点云预处理 去除水面杂点、岸线与桥体反射；保留属于船舶的点 ［3］三维成像与目标分离 对点云做聚类，把同一帧内的多艘船分离为独立目标 每个目标保持跨帧关联，形成稳定编号（track） ［4］尺度测量 对单个目标的点云做姿态估计（首尾朝向） 计算包围盒 → 得到 船长 / 船宽 / 船高 以<水面基准>为下限，输出"船体露出水面高度" ［5］与 AIS / VTS 融合 按 位置 + 时间 关联到具体船舶（匹配到 MMSI） 用登记船长 / 船宽 与雷达测量值做交叉校验（输出偏差率） 结合多帧统计平滑，输出最终高度 ［6］输出 单船三维尺度结果记录 + 超高告警（如需） + 可视化数据

4.4 输出要求

二维/三维相关结果需逐目标落一条记录，字段至少覆盖：

字段组字段
标识时间戳、目标编号、MMSI、船名
雷达测量尺度radar_length_m、radar_width_m、radar_height_m
AIS 登记尺度ais_length_m、ais_width_m
交叉校验长度偏差率、宽度偏差率
融合高度由登记尺度推算高度、最终高度、高度偏差率
点云几何量点云 Z 最小值 / 最大值、目标中心坐标、首尾朝向角、点数
统计与追踪统计窗口样本数 / 时长、尺度离散度、跟踪时长、命中次数

4.5 激光雷达三维成像效果

下图为雷达实际采集的一帧原始点云，以及聚类分离出的单船点云三维重建结果：

图 4-1　激光雷达原始扫描帧（未聚类）：30,868 个点，含水面反射与多艘船舶
图 4-2　单船三维重建——大型船舶：原始簇包围盒 长 126 × 宽 41 × 高 33.2 m
由本图可见预处理的重要性：该目标原始点云簇的包围盒宽度为约 41 m，而该船标注宽度为 25 m——多出的部分来自航行尾迹水花与水面杂点。若直接以原始簇包围盒作为测量结果，宽度将严重偏大。因此点云预处理（水面与杂点抑制）与鲁棒尺度估计是本功能的核心难点，开发时不可省略。图中长与高两个方向与标注值吻合良好，说明船体主体点云质量可靠。
图 4-3　单船三维重建——中型货船：长 49.0 × 宽 11.7 × 高 6.3 m
图 4-4　单船三维重建——小型船舶：长 13.3 × 宽 7.4 × 高 3.2 m
三视图的读法：俯视图反映船长与船宽；侧视图直接反映船高——即本项目测高的核心视图；立体视图用于直观确认三维形态是否完整（有无缺面、是否把水花误当成船体）。

4.6 需要实现的能力清单

  1. 点云接收：稳定接收雷达逐帧点云，具备断线重连与丢帧检测；
  2. 水面与杂点抑制：区分水面反射、岸线、桥体与真实船体点；
  3. 目标聚类与跟踪：同帧内多船分离，跨帧维持稳定编号；
  4. 三维尺度测量：输出长 / 宽 / 高，并给出姿态（首尾朝向）；
  5. 高度基准换算：把点云 Z 值换算为"相对水面的高度"，需接入水位基准数据；
  6. 多帧统计：用一段时间窗口的样本平滑结果，抑制单帧抖动与遮挡；
  7. 与 AIS / VTS 关联：按位置 + 时间匹配到 MMSI；对位置不可信的 AIS 报文需设置门限并排除，宁可不匹配也不误匹配；
  8. 交叉校验与融合：用登记尺度校验雷达测量，输出最终高度；
  9. 结果落盘与可视化：结果记录、目标点云留档，并提供实时可视化数据。
